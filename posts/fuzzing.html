01

Fuzzing이란?

Fuzzing의 정의

퍼징(Fuzzing)은 프로그램에 다양한 입력 데이터를 자동으로 전달하여 예상하지 못한 오류나 보안 취약점을 발견하는 소프트웨어 테스트 기법이다.

일반적인 소프트웨어 테스트에서는 개발자가 예상한 입력값을 사용하여 프로그램이 정상적으로 동작하는지 확인한다. 하지만 퍼징은 정상적인 입력값뿐만 아니라 비정상적인 데이터, 잘못된 형식의 데이터, 매우 큰 데이터 등을 반복적으로 입력하여 프로그램의 동작을 검사한다.

간단한 예시 — 숫자를 입력받는 프로그램에 문자나 매우 큰 숫자를 입력하여 프로그램이 정상적으로 처리하는지 확인하는 것이다.

Fuzzing의 동작 원리

퍼저에 따라 실행 방식은 달라질 수 있지만 일반적인 과정은 다음과 같다.

  1. 초기 입력값 준비테스트에 사용할 정상적인 입력 데이터나 시드(Seed)를 준비한다.
  2. 입력값 생성 및 변형기존 데이터를 변형하거나 새로운 데이터를 생성한다.
  3. 프로그램 실행생성된 데이터를 테스트 대상 프로그램에 전달한다.
  4. 실행 결과 분석프로그램 충돌, 실행 시간 초과, 코드 커버리지 변화 등을 확인한다.
  5. 반복 테스트오류를 일으키거나 새로운 실행 경로를 발견한 입력값을 저장하고 테스트를 반복한다.
02

Fuzzing의 종류

프로그램 내부 정보 활용 방식

블랙박스 퍼징

프로그램의 내부 코드나 구조를 확인하지 않고 입력값과 실행 결과를 중심으로 테스트하는 방식이다.

  • 장점: 소스 코드가 없어도 테스트할 수 있다.
  • 단점: 내부 실행 정보를 활용하지 않으므로 특정 코드 경로를 탐색하기 어려울 수 있다.

화이트박스 퍼징

프로그램의 내부 코드와 구조를 분석하여 테스트 입력값을 생성하는 방식이다. 기호 실행이나 제약 조건 분석 등의 기술을 활용할 수 있다.

  • 장점: 내부 조건을 분석하여 복잡한 실행 경로를 탐지할 수 있다.
  • 단점: 분석 과정에서 많은 시간과 연산 자원이 필요할 수 있다.

그레이박스 퍼징

프로그램의 모든 내부 구조를 분석하지는 않지만 코드 커버리지와 같은 일부 실행 정보를 활용하여 테스트하는 방식이다.

  • 장점: 실행 정보를 활용하여 새로운 코드 경로를 효율적으로 탐색할 수 있다.
  • 단점: 실행 정보를 수집하기 위한 계측 환경이 필요할 수 있다.
구분블랙박스화이트박스그레이박스
내부 정보 활용없음상세 분석일부 활용
주요 정보입력과 결과코드 구조 및 조건코드 커버리지
특징외부 동작 중심내부 분석 중심실행 피드백 중심

입력값 생성 방식

변이 기반 퍼징

기존 입력 데이터를 변경하여 새로운 테스트 데이터를 생성하는 방식이다.

  • 예시: 정상적인 PDF 파일의 일부 바이트를 변경하거나 데이터를 추가·삭제하여 새로운 입력 파일을 만든다.
  • 장점: 기존 데이터를 활용하므로 비교적 간단하게 적용할 수 있다.
  • 단점: 데이터 구조가 손상되어 프로그램의 깊은 처리 단계까지 도달하지 못할 수 있다.

생성 기반 퍼징

미리 정의된 데이터 형식이나 규칙을 바탕으로 새로운 입력값을 생성하는 방식이다.

  • 예시: JSON의 문법과 구조를 고려하여 다양한 테스트 데이터를 생성할 수 있다.
  • 장점: 입력 데이터의 구조를 고려한 테스트가 가능하다.
  • 단점: 데이터 형식과 생성 규칙을 이해하고 구현해야 한다.
구분변이 기반생성 기반
입력값 생성기존 데이터 변경규칙에 따라 생성
특징기존 입력값 활용데이터 구조 활용
한계구조 손상 가능규칙 작성 필요

실행 결과 활용 방식

비피드백 퍼징

이전 테스트에서 얻은 코드 실행 정보를 다음 입력값 생성에 반영하지 않는 방식이다. 단순한 무작위 입력 테스트가 대표적인 예이다.

커버리지 기반 퍼징

프로그램에서 실제로 실행된 코드 정보를 활용하여 새로운 실행 경로를 탐색하는 방식이다. 새로운 코드 경로를 발견한 입력값을 저장하고 다시 변형하여 테스트한다. AFL++, Jackalope, libFuzzer가 대표적이다.

참고 — 위 분류들은 서로 다른 기준이므로 하나의 퍼징 도구가 여러 분류에 동시에 해당할 수 있다.
03

Fuzzer란?

Fuzzer의 정의

퍼저(Fuzzer)는 퍼징을 자동으로 수행하는 소프트웨어 테스트 도구이다.

프로그램에 다양한 입력 데이터를 생성하거나 변형하여 전달하고, 프로그램의 실행 결과를 확인하여 오류나 잠재적인 보안 취약점을 탐색한다.

핵심 차이 — 퍼징(Fuzzing)은 테스트 기법이고, 퍼저(Fuzzer)는 해당 테스트를 수행하는 도구이다.
04

대표적인 Fuzzer의 종류

01 · AMERICAN FUZZY LOP PLUS PLUS

AFL++

정의

AFL++는 기존 AFL을 발전시킨 오픈소스 커버리지 기반 퍼저이다. 프로그램의 코드 실행 정보를 활용하여 새로운 실행 경로를 탐색하고, 다양한 입력값을 반복적으로 전달하여 오류를 발견한다.

주요 특징

  • 코드 커버리지 기반 테스트를 지원한다.
  • 비트 반전, 바이트 변경 등 다양한 입력값 변형 전략을 제공한다.
  • LLVM, QEMU, FRIDA 등 여러 계측 방식을 지원한다.
  • 소스 코드가 있는 프로그램뿐 아니라 특정 모드를 통해 바이너리 프로그램도 테스트할 수 있다.

장단점

장점단점
다양한 변형 전략 제공초기 설정 및 사용법 학습 필요
커버리지 기반의 효율적인 탐색복잡한 입력 형식에서 탐색이 어려울 수 있음
다양한 계측 방식 지원계측 방식에 따라 성능 차이 발생

활용 분야

파일 처리 프로그램, 시스템 라이브러리, 네트워크 서비스 등의 오류 및 보안 취약점 탐색

공식 자료

https://github.com/AFLplusplus/AFLplusplus

02 · GOOGLE PROJECT ZERO

Jackalope

정의

Jackalope는 Google Project Zero에서 공개한 커버리지 기반 퍼저이다. 소스 코드가 없는 바이너리 프로그램을 테스트할 수 있도록 설계되었으며, TinyInst라는 동적 바이너리 계측 도구를 기본적으로 활용한다.

주요 특징

  • 소스 코드가 없는 바이너리 프로그램을 테스트할 수 있다.
  • TinyInst를 이용하여 코드 커버리지 정보를 수집한다.
  • 입력값 변형 및 전달 방식을 사용자 환경에 맞게 수정할 수 있다.
  • 여러 스레드나 컴퓨터를 활용한 병렬 퍼징을 지원한다.

장단점

장점단점
바이너리 프로그램 분석 가능초보자에게 설정이 복잡할 수 있음
사용자 정의 기능 지원고급 변형 기능은 직접 구현해야 할 수 있음
병렬 퍼징 지원테스트 환경 구성 필요

활용 분야

소스 코드가 공개되지 않은 프로그램, 상용 소프트웨어, 바이너리 프로그램의 취약점 분석

공식 자료

https://github.com/googleprojectzero/Jackalope

03 · LLVM

Google Fuzzing과 libFuzzer

정의

libFuzzer는 LLVM 프로젝트에서 제공하는 커버리지 기반 퍼징 엔진이다. 테스트 대상 함수와 같은 프로세스 내부에서 실행되는 In-process 방식을 사용하여 특정 함수를 반복적으로 테스트한다.

Google Fuzzing이란?

Google Fuzzing은 하나의 독립적인 퍼저가 아니라 퍼징 관련 튜토리얼, 예제, 연구 자료 등을 제공하는 GitHub 저장소이다. 따라서 이 자료에서 소개하는 퍼저 중 하나인 libFuzzer를 추가로 살펴본다.

주요 특징

  • 코드 커버리지 기반 퍼징을 지원한다.
  • 테스트 대상 함수를 같은 프로세스 안에서 반복 실행한다.
  • AddressSanitizer 등의 도구와 연동하여 메모리 오류를 탐지할 수 있다.
  • 함수 및 라이브러리 단위 테스트에 적합하다.

장단점

장점단점
빠른 함수 단위 반복 테스트일반적으로 소스 코드와 테스트 하네스 필요
코드 커버리지 활용테스트 간 프로그램 상태가 영향을 줄 수 있음
Sanitizer 연동 가능모든 프로그램에 적합하지는 않음

활용 분야

문자열 처리 함수, 파일 파서, 라이브러리, 데이터 처리 함수 등의 오류 탐색

공식 자료

https://github.com/google/fuzzing/tree/master

퍼저별 핵심 차이

AFL++

다양한 입력값 변형 전략과 계측 방식을 제공하므로 여러 종류의 프로그램을 테스트하는 데 활용할 수 있다.

Jackalope

소스 코드가 없는 바이너리 프로그램을 분석하고 사용자 정의 기능을 활용하는 데 강점이 있다.

libFuzzer

특정 함수나 라이브러리를 같은 프로세스 안에서 반복적으로 테스트하는 데 적합하다.

세 도구 모두 커버리지 정보를 활용하지만 테스트 대상과 실행 방식, 지원 기능에 차이가 있다. 어떤 퍼저가 무조건 더 우수하다고 보기보다는 테스트하려는 프로그램과 환경에 맞는 도구를 선택하는 것이 중요하다.
06

느낀 점

처음 퍼징을 배웠을 때 단순히 무작위 데이터를 프로그램에 입력하여 오류를 찾는 방법이라고 생각했다. 하지만 공부를 더 하면서 퍼징에도 여러 종류가 있고 프로그램의 내부 정보나 코드 커버리지를 활용하여 테스트하는 방식도 있다는 것을 알게 되었다.

또한 AFL++, Jackalope, libFuzzer를 비교하면서 같은 목적을 가진 퍼저라도 테스트 대상과 실행 방식에 따라 특징이 다르다는 점이 신기했다. 특히 소스 코드가 없는 프로그램도 퍼징할 수 있다는 점도 신기했다.

이번 학습을 통해 퍼징이 프로그램의 오류를 발견하는 것뿐만 아니라 소프트웨어의 안정성과 보안성을 높이는 데 활용되는 중요한 테스트 기법이라는 것을 알게 되었다.
